## 📋 실행 계획 개요

### 핵심 전략
**"의존성 분석 → 우선순위 정렬 → 단계적 머징 → 점진적 검증"**

### 왜 이 방법인가?
1. **사전 분석의 가치**: Phase 0의 의존성 분석과 충돌 예측은 **어떤 방법을 선택하든 유용**
2. **위험 분산**: 한 번에 모든 파일을 머징하지 않고 단계별로 수행
3. **검증 가능성**: 각 단계마다 빌드/테스트로 즉시 검증
4. **롤백 용이성**: 문제 발생 시 해당 단계만 롤백
5. **학습 효과**: 초반 단계에서 패턴을 파악하여 후반 가속화

### 3가지 성공 시나리오 (AI 작업 기준)
- **최선**: 분석이 정확하여 대부분 자동 머징 성공 → 2일 (순수 작업 13시간)
- **중간**: 50% 자동, 50% 수동 조정 → 2.5일 (순수 작업 15시간)
- **최악**: 분석 불충분으로 대부분 수동 → 3-4일 (순수 작업 18-20시간)

##### Step 2: 의존성 레벨 계산 (5분)
- **Level 0 (Leaf nodes)**: 다른 both-modified 파일을 import 하지 않음
- **Level 1**: Level 0 파일만 import
- **Level 2**: Level 0-1 파일을 import
- **Level 3+**: 그 이상

**예상 분포**:
- Level 0: 40-50개 (타입 정의, 유틸리티)
- Level 1: 50-60개 (핵심 모듈)
- Level 2: 30-40개 (통합 레이어)
- Level 3+: 10-20개 (엔트리 포인트)

#### 작업 내용

##### Step 1: CARET MODIFICATION 패턴 분석 (10분)

**분석 기준**:

3. **위치**: 파일 상단 vs 중간 vs 하단
4. **주변 코드**: Cline이 자주 수정하는 영역인가?

### 0.3 최적 머징 순서 결정 (20분)

#### 목표
의존성 레벨 + 충돌 위험도를 조합하여 13단계 머징 순서 확정

#### 작업 내용

##### Step 1: 토폴로지 정렬 기본 순서 (5분)

의존성 그래프 기반으로 **Topological Sort** 수행:
```
Level 0 (Leaf) → Level 1 → Level 2 → ... → Level N (Root)
```

**원칙**: 하위 의존성부터 머징하여 상위 레벨에서 이미 안정화된 코드 활용

##### Step 2: 위험도 기반 우선순위 조정 (10분)

동일 레벨 내에서 우선순위:
1. **P3 (Low risk) 먼저**: 빠른 승리(Quick Win)로 confidence 확보
2. **P0 (Critical) 다음**: 초반에 해결하여 블로커 제거
3. **P1-P2 중간**: 패턴 학습 후 처리

**예외 규칙**:
- **Proto 파일**: 항상 최우선 (모든 코드가 의존)
- **Type 정의**: Proto 다음 우선순위
- **Entry point**: 마지막 (extension.ts, App.tsx)

##### Step 3: 13단계 스테이지 구성 (5분)

**Stage 분류 기준**:
```
Stage 1-3: 기초 인프라 (Proto, Types, Utils)
Stage 4-6: 핵심 모듈 (Controller, Task, API)
Stage 7-9: 통합 레이어 (Webview, Integration)
Stage 10-12: 엔트리 포인트 (Extension, App)

```

각 스테이지:
- **최대 15개 파일**: 관리 가능한 단위
- **평균 1-2시간 소요**: 머징 + 검증 + 수정 (AI 작업 기준)

### 0.4 자동화 스크립트 준비 (2시간)

#### 목표
반복 작업을 자동화하여 실행 속도 향상 및 인적 오류 감소

#### 작업 내용

##### Script 1: `scripts/stage-merge.sh` (30분)
```bash
#!/bin/bash
# Usage: ./scripts/stage-merge.sh 1
# 특정 스테이지의 파일들을 순차적으로 머징

STAGE=$1
FILES=$(jq -r ".stages[$STAGE].files[]" .work-logs/merge-stages.json)

for file in $FILES; do
  echo "🔄 Merging $file..."

  # 3-way merge 시도
  git merge-file "$file" \
    "merge-base/$file" \
    "cline-v3.34.0/$file" \
    2>&1 | tee -a ".work-logs/merge-log-stage-$STAGE.txt"

  if [ $? -eq 0 ]; then
    echo "✅ Auto-merge success: $file"
  else
    echo "⚠️ Conflict detected: $file"
    # Conflict markers 분석
    grep -c "<<<<<<< " "$file" >> ".work-logs/conflict-count.txt"
  fi
done
```

##### Script 2: `scripts/verify-stage.sh` (30분)
```bash
#!/bin/bash
# 각 스테이지 머징 후 자동 검증

STAGE=$1

echo "🔍 Stage $STAGE 검증 시작..."

# 1. TypeScript 컴파일
npm run compile 2>&1 | tee ".work-logs/stage-$STAGE-compile.log"
if [ $? -ne 0 ]; then
  echo "❌ Compilation failed"
  exit 1
fi

# 2. 타입 체크
npm run check-types 2>&1 | tee ".work-logs/stage-$STAGE-types.log"
if [ $? -ne 0 ]; then
  echo "❌ Type checking failed"
  exit 1
fi

# 3. 관련 테스트 실행
case $STAGE in
  1|2|3) npm run test:backend:unit ;;
  4|5|6) npm run test:backend:integration ;;
  7|8|9) npm run test:webview ;;
  10|11|12) npm run test:e2e ;;
esac

echo "✅ Stage $STAGE 검증 완료"
```

##### Script 3: `scripts/analyze-conflicts.sh` (30분)
```bash
#!/bin/bash
# Conflict markers를 분석하여 패턴 추출

FILE=$1

echo "=== $FILE ===" >> .work-logs/conflict-analysis.txt

# Conflict 구간 추출
awk '/<<<<<<< /,/>>>>>>> /' "$FILE" >> .work-logs/conflict-analysis.txt

# 패턴 분류
if grep -q "import.*from" "$FILE"; then
  echo "Type: Import conflict" >> .work-logs/conflict-patterns.txt
elif grep -q "CARET MODIFICATION" "$FILE"; then
  echo "Type: CARET MODIFICATION overlap" >> .work-logs/conflict-patterns.txt
elif grep -q "function\|class\|export" "$FILE"; then
  echo "Type: Function/Class definition conflict" >> .work-logs/conflict-patterns.txt
fi
```

##### Script 4: `scripts/rollback-stage.sh` (30분)
```bash
#!/bin/bash
# 특정 스테이지를 롤백하고 재시도

STAGE=$1

echo "⏪ Rolling back Stage $STAGE..."

# 1. 해당 스테이지 커밋 찾기
COMMIT=$(git log --grep="Stage $STAGE" --format="%H" -n 1)

# 2. 해당 커밋만 revert
git revert --no-commit $COMMIT

# 3. 스테이지 파일들만 복구
FILES=$(jq -r ".stages[$STAGE].files[]" .work-logs/merge-stages.json)
for file in $FILES; do
  git checkout HEAD~1 -- "$file"
done

git commit -m "Rollback Stage $STAGE for retry"

echo "✅ Rollback 완료. 수동 머징으로 재시도 가능"
```
