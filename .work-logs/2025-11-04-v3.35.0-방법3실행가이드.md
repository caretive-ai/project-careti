## 🎯 머징 패턴

### Pattern A: Caret Dominant
```typescript
// Caret 변경이 크고, Cline 변경이 작을 때
// → Caret 유지 + Cline 체리픽

// 예: src/extension.ts
```

**작업**:
1. Caret 버전 적용
2. Cline 개선 사항 확인
3. 필요한 부분만 수동 추가

---

### Pattern B: Cline Dominant
```typescript
// Cline 변경이 크고 (리팩토링), Caret 변경이 작을 때
// → Cline 수용 + Caret 재적용

// 예: src/core/task/index.ts

// CARET MODIFICATION: Re-applied feature
function newClineFunction() {
  // Caret additions
  Logger.debug(`[${brand}] ...`)

  // Cline logic
  // ...
}
```

**작업**:
1. Cline 버전 적용
2. Caret 변경 추출
3. Cline 구조에 맞춰 재적용
4. CARET MODIFICATION 주석

---

### Pattern C: Hybrid
```typescript
// 양쪽 모두 중요한 변경
// → Cline 구조 + Caret 기능 통합

// 예: src/core/controller/index.ts

class Controller {
  // Cline improved methods
  async handleMessage(message: Message) {
    // Cline routing
    // ...

    // CARET MODIFICATION: Caret message types
    if (message.type.startsWith('caret/')) {
      return this.handleCaretMessage(message)
    }
  }

  // CARET MODIFICATION: Caret-specific handlers
  private async handleCaretMessage(message: CaretMessage) {
    // ...
  }
}
```

**작업**:
1. Cline 구조 적용
2. Caret 핸들러 추가
3. Integration 지점 연결
4. CARET MODIFICATION 주석

---

### Pattern D: i18n Integration (Webview)
```tsx
// Cline UI 개선 + Caret i18n
// → Cline UI + t() 함수 적용

// Before (Cline)
<button>Save Settings</button>

// After (Caret + Cline)
import { t } from '@/utils/i18n'

<button>
  {t('settings.save', 'common')}
</button>
```

**작업**:
1. Cline UI 구조 적용
2. 모든 text를 t() 함수로 변환
3. i18n key가 존재하는지 확인
4. 없으면 locales/*.json에 추가

---

### Pattern E: Proto Fields
```protobuf
// Cline 필드: 1-[max]
// Caret 필드: 1072+

message ModelsApiConfiguration {
  // Cline fields
  string anthropic_api_key = 1;
  // ...
  string last_cline_field = 72;

  // CARET MODIFICATION: Caret-specific fields (72 + 1000 = 1072+)
  string requesty_api_key = 1072;
  string code_center_endpoint = 1073;
  // ...
}
```

**작업**:
1. Cline 최대 field 번호 확인
2. Caret field가 max + 1000 이상인지 확인
3. Comment 업데이트
4. `npm run protos` 실행

## ⚠️ 주의사항

### DO ✅

1. **항상 3-way diff로 시작**
   ```bash
   ./scripts/3way-diff.sh [파일]
   ```

2. **변경 이해 우선**
   - 왜 Caret이 이렇게 변경했나?
   - 왜 Cline이 이렇게 변경했나?
   - 어떻게 통합할 것인가?

3. **CARET MODIFICATION 주석 필수**
   ```typescript
   // CARET MODIFICATION: [설명]
   ```

4. **각 Stage 후 검증**
   ```bash
   npm run compile
   npm run check-types
   npm run test:backend
   ```

5. **작은 단위로 commit**
   - Stage별로 commit
   - 명확한 메시지

---

### DON'T ❌

1. **코드 디버깅하지 말 것**
   - Git blame 보지 말것
   - "왜 안돼?"하지 말것
   - 3-way diff로 이해 우선

2. **Conflict markers에 의존하지 말 것**
   ```typescript
   <<<<<<< HEAD
   // 이거 보고 판단하지 말것
   =======
   >>>>>>> cline-latest
   ```
   → 3-way diff 사용

3. **전체 파일 덮어쓰지 말 것**
   - ❌ `git checkout --theirs [파일]`
   - ❌ `git checkout --ours [파일]`
   - ✅ 수동 통합

4. **테스트 건너뛰지 말 것**
   - 매 Stage 검증 필수
   - 나중에 문제 발생 시 원인 찾기 어려움

5. **주석 없이 수정하지 말 것**
   - Caret 코드에는 반드시 CARET MODIFICATION

## 🎓 핵심 원칙

### 1. 이해 우선 (Understand First)
```
코드 수정 전에 반드시:
- Caret이 왜 변경했는지 이해
- Cline이 왜 변경했는지 이해
- 통합 방법 계획

❌ 일단 수정하고 컴파일 → 디버깅 지옥
✅ 이해하고 수정 → 한 번에 성공
```

### 2. 작은 단위 (Small Steps)
```
- Stage별로 진행
- 각 Stage 후 검증
- 문제 즉시 발견 및 해결

❌ 여러 Stage 한꺼번에 → 문제 원인 모름
✅ Stage 하나씩 → 문제 즉시 해결
```

### 3. 명확한 표시 (Clear Marking)
```typescript
// CARET MODIFICATION: [명확한 설명]

❌ 주석 없이 수정 → 6개월 후 "이게 뭐지?"
✅ 명확한 주석 → 즉시 이해 가능
```

### 4. 철저한 검증 (Thorough Verification)
```bash
# 매 Stage 후
npm run compile        # ✅
npm run check-types    # ✅
npm run test:backend   # ✅

❌ 나중에 한꺼번에 테스트 → 디버깅 지옥
✅ 즉시 검증 → 문제 즉시 해결
```

### 5. 디버깅 금지 (No Debugging)
```
❌ 컴파일 안돼 → 이것저것 시도 → 더 꼬임
✅ 컴파일 안돼 → 3-way diff → 이해 → 수정
```

## 🔄 일반적인 Workflow

### 파일 하나 머징하기

```bash
# 1. 분석 (10-20분)
./scripts/3way-diff.sh src/path/to/file.ts

# 질문:
# - Caret이 뭘 추가했나?
# - Cline이 뭘 변경했나?
# - 어떻게 통합할까?

# 2. 전략 선택 (5분)
# Pattern A/B/C/D/E 중 선택

# 3. 코드 수정 (10-30분)
code src/path/to/file.ts

# 4. 검증 (5분)
npm run compile
npm run check-types

# 5. 테스트 (5-10분)
npm run test:backend -- src/path/to/__tests__/file.test.ts

# 6. 완료
✅ Done!
```

---

### Stage 하나 완료하기

```bash
# 1. Stage 시작
echo "Stage N: [Title]" >> .work-logs/stage-log.txt
date >> .work-logs/stage-log.txt

# 2. 파일들 머징 (반복)
for file in [files]; do
  ./scripts/3way-diff.sh $file
  # 분석 → 수정 → 검증
done

# 3. Stage 검증
npm run compile
npm run check-types
npm run test:backend

# 4. Manual test
# Extension Dev Host에서 기능 확인

# 5. Commit
git add [files]
git commit -m "merge(stage-N): [Title] ..."

# 6. 완료 기록
echo "Completed: $(date)" >> .work-logs/stage-log.txt
```
