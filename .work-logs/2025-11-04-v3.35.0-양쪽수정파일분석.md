## 충돌 해결 패턴

### Pattern A: Caret Dominant (Cline 경미)
```typescript
// Caret가 구조적 변경, Cline이 작은 개선
// → Caret 유지 + Cline 체리픽

// 예: src/extension.ts
```

### Pattern B: Cline Dominant (Caret 최소)
```typescript
// Cline이 대규모 리팩토링, Caret이 작은 추가
// → Cline 수용 + Caret 재적용

// 예: src/core/task/index.ts
// CARET MODIFICATION: Re-applied Caret features
```

### Pattern C: Hybrid (양쪽 중요)
```typescript
// 양쪽 모두 구조적 변경
// → Cline 구조 + Caret 기능 통합

// 예: src/core/controller/index.ts
// Section 1: Cline message routing (improved)
// Section 2: CARET MODIFICATION: Caret gRPC handlers
```

### Pattern D: i18n Integration (Webview)
```typescript
// Cline UI 개선 + Caret i18n 추가
// → Cline UI + t() 함수 적용

// 예: SettingsView.tsx
const { t } = useCaretI18n()
// ... Cline의 개선된 UI
<button>{t('settings.save', 'common')}</button>
```

### Pattern E: Proto Fields
```protobuf
// Cline 필드: 1-[max]
// Caret 필드: 1072+
// → Field numbering 유지

message ModelsApiConfiguration {
  // Cline fields (1-72)
  string anthropic_api_key = 1;
  // ...

  // CARET MODIFICATION: Caret-specific fields (72 + 1000 = 1072+)
  string requesty_api_key = 1072;
  // ...
}
```
