# Task 026: 모드 별 AI 행동 제약 및 소통 오류 개선

### 1. 개요 (Overview)
- **목표:** `Agent` 모드와 `Chatbot` 모드의 특성에 맞게 AI의 행동 제약 규칙을 세분화하고, AI가 시스템 제약에 대해 사용자와 명확하게 소통할 수 있도록 개선합니다.
- **우선순위:** 보통 (현재 진행 중인 머지 작업 완료 후 진행)

### 2. 문제 현상 (Problem Description)

현재 시스템은 각 모드의 특성을 고려하지 않은 일괄적인 규칙을 적용하여 두 가지 다른 문제를 야기하고 있습니다.

**Case 1: 에이전트 모드의 대화 제약 문제 (기존 문제)**
- **현상:** `Agent` 모드에서 AI가 도구 사용 없이 순수한 대화(예: 질문, 확인)를 시도할 경우, 시스템이 이를 허용하지 않고 아래와 같은 에러를 발생시킵니다.
  ```
  [ERROR] You did not use a tool in your previous response! Please retry with a tool use.
  ```
- **영향:** `Agent` 모드가 유연한 문제 해결 대신 기계적인 도구 실행만 강요받게 되어, 협력적인 개발 파트너로서의 역할을 수행할 수 없습니다.

**Case 2: 챗봇 모드의 도구 사용 제약 문제 (신규 발견)**
- **현상:** `Chatbot` 모드에서 AI는 `read-only` 도구만 사용하도록 제한되어 있어, 세션 전환을 위한 `new_task`와 같은 쓰기(write) 권한이 필요한 도구를 사용할 수 없습니다.
- **영향:** AI는 명확한 해결책(`new_task` 사용)을 알고 있음에도 불구하고 실행할 수 없어, `next-session-guide.md` 파일을 수동으로 생성하는 등 비효율적인 우회책을 시도하게 됩니다. 또한, 이러한 제약 상황을 사용자에게 명확히 설명하지 못하고 혼란을 야기합니다.

### 3. 원인 분석 (Root Cause Analysis)
- **공통 원인:** AI의 응답을 처리하는 최상위 로직이 `Agent`와 `Chatbot` 모드의 컨텍스트와 목적을 구분하지 않고, 획일적인 규칙(예: 도구 사용 여부, 도구 접근 권한)을 적용하기 때문입니다.
- **Case 1 원인:** `Agent` 모드의 응답 유효성을 검사할 때, '대화'를 유효한 행동으로 간주하지 않고 '도구 사용'만을 강제합니다.
- **Case 2 원인:** `Chatbot` 모드에 할당된 도구 목록이 너무 제한적이어서, 상담 및 분석에 필요한 최소한의 상태 저장/전환(`new_task`)과 같은 핵심 기능을 수행할 수 없습니다.

### 4. 해결 방안 (Proposed Solution)
1.  **에이전트 모드 대화 허용:** `Agent` 모드의 응답 유효성 검사 로직을 수정하여, 도구 사용(`tool_use`) 뿐만 아니라 순수 대화형 응답도 허용하도록 변경합니다. (`"You did not use a tool..."` 에러 로직 수정)
2.  **챗봇 모드 도구 권한 재설계:** `Chatbot` 모드의 역할을 재정의하고, '상담 및 분석' 목적에 부합하는 최소한의 쓰기 도구(예: `new_task`) 사용을 허용하는 것을 검토합니다.
3.  **AI 소통 능력 강화:** AI가 현재 모드의 제약으로 인해 특정 작업을 수행할 수 없을 때, 사용자에게 해당 상황과 필요한 조치(예: 모드 전환 요청)를 명확하게 설명하고 안내할 수 있도록 시스템 프롬프트 또는 로직을 개선합니다.

### 5. 완료 조건 (Definition of Done)
- `Agent` 모드에서 AI가 도구 사용 없이 자유롭게 사용자에게 질문하거나 대화할 수 있어야 합니다.
- `Chatbot` 모드에서 AI가 세션 전환과 같은 필수적인 작업을 수행할 수 있는 합리적인 방법을 갖추어야 합니다.
- AI는 각 모드의 제약사항에 대해 사용자에게 명확하게 설명할 수 있어야 합니다.
