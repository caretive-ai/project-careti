## 🔧 구현 전략

### **핵심 접근법: 2단계 브랜드 변환**

#### **현재 i18n 구조의 한계**
- **하드코딩된 import**: 30개 JSON 파일을 i18n.ts에 직접 import
- **확장성 문제**: 새 locale 추가 시 i18n.ts 수정 필수
- **브랜드 변환 복잡도**: caret ↔ codecenter 시 i18n.ts도 수정 필요

#### **Stage 1: cline ↔ caret (코드 레벨 변환)**
- 하드코딩 텍스트 → i18n 키 대체
- `"Cline wants to"` → `{t('CARET.BRAND')} wants to`
- TSX 파일 직접 수정

#### **Stage 2: caret ↔ codecenter (파일 교체 방식)**
- **locale 폴더**: JSON 파일 전체를 백업/교체
- **i18n.ts**: 파일 자체를 브랜드별로 교체
- `caret-b2b/brands/caret/` 에 Caret 버전 저장
- `caret-b2b/brands/codecenter/` 에 CodeCenter 버전 보관

#### **Phase 1: 최소 침습적 i18n 통합**
1. **Level 1 아키텍처 유지**
   - `/src/caret/` 폴더 내 독립적 i18n 시스템
   - 기존 Cline 코드 최소 수정
   - CARET MODIFICATION 주석으로 추적

2. **i18n 키 기반 렌더링**
   ```typescript
   // 예시: ChatRow.tsx 변환 전

   import { t } from '@/caret/utils/i18n'
   <span>{t('CARET.BRAND')} wants to execute this command:</span>
   
   // locale/en/common.json
   {
     "CARET": {
       "BRAND": "Cline"  // cline 모드
       // "BRAND": "Caret" // caret 모드
       // "BRAND": "CodeCenter" // codecenter 모드
     }
   }
   ```

3. **i18n 통합 전략**
   - 모든 하드코딩 텍스트를 i18n 키로 대체
   - locale JSON 파일에서 브랜드별 텍스트 관리
   - brand-converter.js가 코드 변환 처리
