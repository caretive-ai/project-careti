## 🎯 작업 목적

### **왜 이 작업이 필요한가?**
- 프론트엔드에 하드코딩된 "Cline" 텍스트들이 브랜드 변환되지 않음
- caret-main에서 이미 구현된 다국어 지원 웰컴페이지를 활용 가능
- 디자인 변경된 페이지들을 효율적으로 이식 필요

### **이 작업의 목표**
- 프론트엔드 i18n 적용 및 브랜드 변환 가능하게 만들기
- caret-main의 웰컴페이지 및 다국어 기능 이식
- brand-converter.js로 프론트엔드도 일괄 변환 가능하게

## 📝 작업 계획

### **1. 프론트 i18n 적용**
#### **1.1. 디자인 변경 없는 i18n 페이지 이식**
- caret-main에서 다국어 적용된 페이지 리스팅
- 변경이 적은 페이지들을 brand-config.json에 추가 (배치 변환용)
- brand-converter.js로 cline ↔ caret 상호 변환 테스트
- 개발자 확인 후 커밋/푸시
- codecenter 브랜드 변환 스크립트 작성 및 테스트
- codecenter 상태에서 릴리즈 vsix 파일 생성
- caret 상태로 복원 후 커밋/푸시

#### **1.2. 디자인 변경된 페이지 이식 (웰컴페이지 등)**
- caret-main의 웰컴페이지 이식 (환영 텍스트, 언어 설정, 모델 설정 포함)
- 과도하게 변경된 소스는 `caret-b2b/brands/caret/file-replace/`로 백업
- brand-converter.js에 파일 교체 기능 추가
- cline ↔ caret 상호 변환 테스트
- codecenter 브랜드 변환 작성 및 테스트
- 릴리즈 및 커밋/푸시

#### **1.3. 누락된 프론트 하드코딩 텍스트 i18n 추가**
- 미사용 i18n 코드 정리
- Cline에서 새로 추가된 영역의 번역되지 않은 문자열 찾기
- i18n 추가 및 brand-config.json 업데이트
- 테스트 및 릴리즈

## 📋 웰컴페이지 이식 상세 계획 (참고용)

> **참고**: 아래 내용은 웰컴페이지 이식 시 참고할 수 있는 기존 계획입니다.

### 핵심 취지
- **caret-main 기능 활용**: 기존에 구현된 i18n 웰컴페이지 시스템을 caret-merging으로 이식
- **자동 브랜딩 전환**: i18n 적용 페이지의 하드코딩된 텍스트를 자동으로 cline ↔ caret ↔ codecenter 전환
- **업스트림 호환성**: cline 원본과 최대한 호환되면서도 브랜딩 기능 제공

### 핵심 방향
1. **Level 1 독립 모듈**: 웹뷰의 `/src/caret/` 폴더 활용으로 충돌 최소화
2. **주석 기반 추적**: `// CARET MODIFICATION:` 표준으로 변경사항 표시
3. **자동 복구 시스템**: 브랜드별 하드코딩 텍스트 자동 저장/복원 메커니즘

### 🔧 3.2 i18n 페이지 자동 cline 전환 시스템 개발

#### **A. 하드코딩 텍스트 자동 감지**
```javascript
// 구현 목표: 하드코딩된 브랜드명 자동 감지 및 매핑
class I18nBrandTextDetector {
  detectHardcodedBrandText(filePath: string): HardcodedText[]
  createI18nKeyMapping(hardcodedTexts: HardcodedText[]): I18nKeyMapping
  generateAutoReplacementRules(): ReplacementRule[]
}
```

#### **B. 브랜드별 백업/복원 시스템**
```typescript
// 목표: 브랜드 전환 시 하드코딩 텍스트 자동 백업/복원
interface BrandTextBackup {
  brand: 'cline' | 'caret' | 'codecenter'
  filePath: string
  originalTexts: Record<string, string>  // 원본 하드코딩 텍스트
  i18nKeys: Record<string, string>       // 대응되는 i18n 키
}
```

#### **C. 자동 전환 스크립트 확장**

## 🚨 중요 제약사항 및 원칙

- **백업 의무**: 변경 전 반드시 `.cline` 백업 생성
