## 핵심 빌드 워크플로우

Careti 프로젝트는 여러 구성 요소(Extension Backend, Webview UI, CLI)로 이루어져 있으며, 각 부분은 의존성을 가집니다. 일반적인 전체 빌드 순서는 다음과 같습니다.

1.  **프로토콜 버퍼 코드 생성 (`npm run protos`)**:
    gRPC 통신을 위한 TypeScript/JavaScript 코드를 먼저 생성합니다. 이는 백엔드와 웹뷰 모두에 필요합니다.

2.  **의존성 설치 (`npm run install:all`)**:
    루트 디렉토리와 `webview-ui` 디렉토리의 모든 npm 의존성을 설치합니다.

3.  **웹뷰 UI 빌드 (`npm run build:webview`)**:
    React 기반의 웹뷰 UI를 프로덕션용으로 빌드합니다.

4.  **전체 타입 검사 및 린팅 (`npm run check-types` & `npm run lint`)**:
    프로젝트 전체의 코드 품질과 타입 안정성을 검사합니다.

5.  **메인 익스텐션 컴파일 (`npm run compile`)**:
    `esbuild`를 사용하여 최종 `dist/extension.js` 파일을 생성합니다. 이 과정은 타입 검사와 린팅을 포함합니다.

## 주요 개발 스크립트

일상적인 익스텐션 백엔드 개발에 필수적인 기본 스크립트입니다.

### `npm run compile`

- **설명**: 프로젝트의 메인 빌드 명령어입니다. `check-types:backend`, `lint`, `esbuild` 번들링을 순차적으로 실행하여 `dist/extension.js` 결과물을 생성합니다.
- **사용 시기**: 코드 변경 후 전체 빌드가 필요할 때 사용합니다.

### 빠른 컴파일 (단축 명령 없음)

- **설명**: 타입 체크와 린트를 건너뛰고 빌드만 빠르게 수행하려면 `node esbuild.mjs`를 직접 실행할 수 있습니다.
- **명령어**: `node esbuild.mjs`
- **사용 시기**: 빠른 피드백 루프가 필요한 로컬 개발 시 유용합니다.

### `npm run watch`

- **설명**: 개발 중 파일 변경 사항을 감지하여 자동으로 재빌드하는 감시 모드를 실행합니다. VSCode 개발 창(F5)을 열어두고 실시간으로 변경 사항을 테스트할 때 유용합니다.
- **사용 시기**: 지속적인 코드 수정 및 테스트가 필요한 개발 세션 중에 사용합니다.

### `npm run check-types`

- **설명**: `tsc` (TypeScript Compiler)를 사용하여 프로젝트 전체(백엔드 및 프론트엔드)의 타입 오류를 검사합니다. `tsconfig.json`의 `noEmit: true` 설정에 따라 JavaScript 파일을 생성하지는 않고 오직 타입 검증만 수행합니다.
- **사용 시기**: 코드를 구현하면서 타입이 올바른지 빠르게 확인할 때 사용합니다.

### `npm run lint`

- **설명**: Biome 린터를 사용하여 프로젝트의 코드 스타일과 포맷 규칙을 검사하고 수정합니다.
- **사용 시기**: 코드 커밋 전이나 코드 품질을 확인할 때 사용합니다.

## Webview 개발 스크립트

React 기반의 프론트엔드(Webview) 개발에 사용되는 스크립트입니다.

### `npm run dev:webview`

- **설명**: Vite 개발 서버를 실행하여 웹뷰 UI를 개발합니다. `watch` 스크립트와 함께 실행하면 백엔드와 프론트엔드 변경사항을 실시간으로 확인할 수 있습니다.
- **사용 시기**: UI 컴포넌트 개발 및 프론트엔드 로직을 수정할 때 사용합니다.

### `npm run build:webview`

- **설명**: 프로덕션용으로 웹뷰 코드를 빌드하고 최적화합니다. 최종 익스텐션 패키징에 포함될 정적 에셋을 생성합니다.
- **사용 시기**: 릴리즈 버전을 빌드하거나, 최종 프로덕션 환경에서 웹뷰가 올바르게 동작하는지 확인할 때 사용합니다.

## 테스트 스크립트

프로젝트의 안정성을 보장하기 위한 다양한 테스트 스크립트입니다.

### `npm test` 또는 `npm run test`

- **설명**: 전체 테스트 스위트(단위 및 통합 테스트)를 실행합니다.
- **사용 시기**: 모든 기능이 정상적으로 동작하는지 종합적으로 확인할 때 사용합니다.

### `npm run test:unit`

- **설명**: Mocha를 사용하여 익스텐션 호스트(Node.js)의 백엔드 로직에 대한 단위 테스트를 실행합니다.
- **사용 시기**: 백엔드 서비스, 컨트롤러, 유틸리티 등 핵심 로직을 개발할 때 사용합니다.

### `npm run test:webview`

- **설명**: Vitest를 사용하여 웹뷰(React) 컴포넌트 및 프론트엔드 로직에 대한 단위/통합 테스트를 실행합니다.
- **사용 시기**: UI 컴포넌트나 프론트엔드 관련 기능을 개발할 때 사용합니다.

### `npm run test:e2e`

- **설명**: Playwright를 사용하여 엔드 투 엔드(E2E) 테스트를 실행합니다. 실제 VSCode 환경에서 익스텐션을 실행하여 사용자 시나리오를 시뮬레이션합니다.
- **사용 시기**: 주요 기능의 전체 워크플로우가 올바르게 작동하는지 검증할 때 사용합니다.

## CLI 및 프로토콜 버퍼 스크립트

Careti CLI 및 gRPC 통신과 관련된 스크립트입니다. 자세한 내용은 `cli-development.md` 문서를 참고하세요.

### `npm run protos`

- **설명**: `proto/` 디렉토리의 `.proto` 파일들을 기반으로 TypeScript/JavaScript용 gRPC 클라이언트 및 서버 코드를 자동 생성합니다.
- **사용 시기**: 프로토콜 버퍼 정의를 수정했거나 새로 추가했을 때 반드시 실행해야 합니다.

### `npm run protos-go`

- **설명**: Go 언어로 작성된 CLI를 위한 gRPC 클라이언트 코드를 생성합니다.
- **사용 시기**: CLI 관련 프로토콜 버퍼를 수정한 후 CLI를 빌드하거나 테스트하기 전에 실행합니다.

### `npm run compile-cli`

- **설명**: 현재 운영체제에 맞는 Careti CLI 바이너리를 빌드합니다.
- **사용 시기**: CLI 기능을 개발하고 테스트할 때 사용합니다.

## 릴리즈 및 패키징

개발이 완료된 익스텐션을 배포 가능한 파일로 만드는 스크립트입니다.

### `npm run package`

- **설명**: `vsce package` 명령어를 사용하여 전체 프로젝트를 `.vsix` 확장 파일로 패키징합니다. 이 파일은 VSCode Marketplace에 업로드하거나 직접 설치하는 데 사용됩니다.
- **사용 시기**: 배포용 파일을 생성할 때 사용합니다.

### `npm run package:release`

- **설명**: 프로덕션 릴리즈를 위한 패키징 스크립트입니다.
- **사용 시기**: 공식 릴리즈 버전을 생성할 때 사용합니다.

## 문제 해결 (Troubleshooting)

### 🚨 코드를 수정했지만 빌드에 변경 사항이 반영되지 않는 경우

가장 일반적인 원인은 `src/` 또는 `careti-src/` 디렉토리에 이전 빌드에서 생성된 `.js` 또는 `.js.map` 파일이 남아있는 경우입니다. Careti의 빌드 시스템은 `tsc`를 타입 체크 전용으로 사용하고(`noEmit: true`), 실제 JavaScript 번들은 `esbuild`가 생성합니다. 소스 디렉토리에 `.js` 파일이 있으면, 번들된 최신 코드 대신 이전 `.js` 파일이 로드될 수 있습니다.

#### 해결 방법

1.  **소스 디렉토리의 `.js` 파일 정리**:
    다음 명령을 실행하여 `src/` 및 `careti-src/` 내의 모든 `.js`와 `.js.map` 파일을 삭제합니다.

    ```bash
    find src careti-src -name "*.js" -o -name "*.js.map" | xargs rm -f
    ```

2.  **VSCode 창 새로고침**:
    `Command Palette` (`Cmd+Shift+P` 또는 `Ctrl+Shift+P`)를 열고 `Developer: Reload Window`를 실행하여 VSCode 편집기 창을 새로고침합니다. 이렇게 하면 확장 프로그램이 새로운 빌드 결과를 올바르게 로드합니다.
