# 상세 영향도 분석 보고서 (파일 상태 기반)

## 1. 개요
이 문서는 `git diff --name-status`를 통해 생성된 파일 변경 목록을 기반으로, Cline upstream 브랜치와 Caret 브랜치 간의 상세한 차이점을 분석합니다. 분석은 다음 세 가지 범주로 나누어 수행됩니다.

1.  **Cline에서 삭제된 파일** (및 Caret과의 충돌 여부)
2.  **Cline에 새로 추가된 파일**
3.  **Caret과 Cline 양쪽 모두에서 수정된 파일**

## 2. 분석 결과

### 2.1. Cline에서 삭제된 파일 및 영향도

Cline의 최신 버전에서는 여러 파일이 삭제되거나 이름이 변경되었습니다. 대부분은 리팩토링의 일부이지만, 일부는 Caret이 수정한 파일과 겹쳐 병합 시 충돌을 일으킵니다.

- **삭제/수정 충돌 (🔴 고위험)**:
  - `src/core/prompts/system-prompt-legacy/generic-system-prompt.ts`: Cline은 이 레거시 프롬프트 파일을 삭제했지만, Caret은 이 파일을 수정하여 사용 중입니다. Caret의 프롬프트 시스템 로직을 새로운 Cline 구조에 맞게 재구현해야 합니다.
  - **영향도**: 높음. Caret의 핵심 프롬프트 로직 중 일부가 의존하는 파일이므로, 해당 로직을 새로운 프롬프트 시스템으로 마이그레이션해야 합니다.

- **단순 삭제 (🟢 저위험)**:
  - `proto/host/watch.proto`: 파일 감시 관련 API가 다른 방식으로 대체된 것으로 보입니다.
  - `scripts/test-ci.js`: `package.json` 스크립트로 통합되었습니다.
  - `src/core/controller/browser/updateBrowserSettings.ts`: 관련 기능이 리팩토링되었습니다.
  - `webview-ui/src/utils/vscode.ts`: 더 이상 사용되지 않는 유틸리티 파일입니다.
  - **영향도**: 낮음. Caret이 의존하지 않는 파일들이므로, 병합 시 자연스럽게 삭제를 반영하면 됩니다.

### 2.2. Cline에 새로 추가된 파일 및 영향도

Cline은 여러 가지 새로운 기능과 시스템을 추가했습니다. 이 파일들은 직접적인 충돌은 없지만, Caret의 아키텍처에 통합하는 작업이 필요합니다.

- **주요 추가 기능**:
  - `cli/` (전체 디렉토리): Go 언어로 작성된 새로운 커맨드 라인 인터페이스입니다.
  - `testing-platform/` (전체 디렉토리): 새로운 테스트 플랫폼으로 보입니다.
  - `src/core/workspace/` (전체 디렉토리): 멀티-루트 작업 공간 지원을 위한 새로운 시스템입니다.
  - `src/core/locks/`: 동시성 제어를 위한 새로운 잠금 관리 시스템입니다.
  - `src/services/telemetry/`, `src/services/error/`, `src/services/feature-flags/`: 원격 측정, 오류 보고, 기능 플래그 시스템이 대대적으로 리팩토링 및 확장되었습니다.
  - `src/core/api/providers/oca.ts` 및 관련 파일: 새로운 `OCA` API 제공자가 추가되었습니다.
- **영향도**: 중간. 이 새로운 기능들은 Caret에 포팅할지, 아니면 기존 Caret 시스템과 어떻게 조화시킬지 아키텍처 결정이 필요합니다. 특히 `workspace`와 `telemetry` 시스템은 Caret의 기존 기능과 면밀한 통합 검토가 필요합니다.

### 2.3. Caret과 Cline 양쪽 모두에서 수정된 파일 (병합 충돌)

아래 파일들은 양쪽 브랜치에서 모두 수정되었기 때문에, 병합 시 **반드시 수동으로 충돌을 해결해야 하는** 파일들입니다. 충돌 해결 난이도가 가장 높은 최상위 위험 그룹입니다.

- **핵심 아키텍처 파일 (🔴 최고 위험)**:
  - `package.json`: 의존성 및 빌드 스크립트 충돌. (테스트 프레임워크 `mocha` vs `vitest` 등)
  - `proto/cline/models.proto`: API 데이터 구조 충돌. (`ApiProvider` enum 값 충돌 등)
  - `src/extension.ts`: 익스텐션 진입점 및 초기화 로직 충돌.
  - `src/core/webview/WebviewProvider.ts`: 웹뷰 제공자 핵심 로직 충돌.

- **상태 관리 및 통신 (🔴 고위험)**:
  - `src/shared/ExtensionMessage.ts`: 프론트-백엔드 메시지 프로토콜 충돌.
  - `src/core/storage/StateManager.ts`: 전역 상태 관리 로직 충돌.
  - `src/core/storage/state-keys.ts`: 상태 데이터 구조 정의 충돌.
  - `src/core/storage/utils/state-helpers.ts`: 상태 초기화 및 헬퍼 함수 충돌.

- **UI 컴포넌트 (🔴 고위험)**:
  - `webview-ui/src/components/settings/ApiOptions.tsx`: API 제공자 선택 UI 로직 충돌.
  - `webview-ui/src/components/settings/SettingsView.tsx`: 설정 화면 전체 레이아웃 및 로직 충돌.
  - `webview-ui/src/components/welcome/WelcomeView.tsx`: 초기 화면 UI 및 로직 충돌.
  - `webview-ui/src/components/chat/ChatView.tsx`: 채팅 화면 핵심 로직 충돌.
  - `webview-ui/src/components/chat/ChatTextArea.tsx`: 채팅 입력창 로직 충돌.

- **영향도**: 최고. 이 파일들은 프로젝트의 근간을 이루며, 잘못 병합될 경우 전체 애플리케이션이 동작하지 않을 수 있습니다. `final-merge-strategy.md`에 기술된 대로, Cline의 버전을 기준으로 Caret의 변경 사항을 하나씩 신중하게 재적용하는 방식이 필요합니다.
