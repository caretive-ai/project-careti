# 최종 Cline Upstream 병합 실행 계획 (AI 수행용)

## 1. 배경 및 목표
- **상황**: `Caret`은 `Cline`의 포크(fork) 프로젝트입니다. `Caret`은 독자적인 기능(계정, 페르소나, i18n, 프롬프트 시스템 등)을 추가하며 원본(`upstream`)과 상당한 차이가 발생했습니다.
- **목표**: `Cline`의 최신 변경 사항을 `Caret`에 안전하게 통합하여 최신 상태를 유지하면서도, `Caret`의 고유한 정체성과 기능을 완벽하게 보존합니다.

## 2. 핵심 제약 조건 및 원칙
- **수동 병합**: 단순 `git merge`는 불가능합니다. 모든 충돌은 Cline의 최신 코드를 기준으로, Caret의 변경 사항을 수동으로 재적용하는 방식으로 해결합니다.
- **Caret 기능 보존**: Caret의 핵심 기능(계정, 페르소나, i18n, 이중 프롬프트 시스템, `vitest` 테스트 환경 등)은 반드시 유지되어야 합니다.
- **단계별 검증**: 각 주요 단계를 완료한 후에는 반드시 컴파일(`npm run compile`) 및 테스트(`npm run test:webview`)를 통해 안정성을 확인합니다.
- **브랜딩 유지**: 모든 사용자 인터페이스와 내부 식별자(명령어, 컨텍스트 키 등)는 `Caret` 브랜드를 유지해야 합니다.

## 3. 분석 요약 (주요 충돌 지점)
- **🔴 최고 위험 (아키텍처 충돌)**:
  - `package.json`: 테스트 프레임워크(`mocha` vs `vitest`) 및 의존성/스크립트 충돌.
  - `proto/cline/models.proto`: API 데이터 구조의 핵심인 `ApiProvider` enum 값(`35`)이 충돌합니다.
  - `src/extension.ts`: 익스텐션 초기화 로직 및 아키텍처(`CaretProviderWrapper`)가 완전히 다릅니다.
- **🟠 고위험 (기능 충돌)**:
  - **상태 관리**: `ExtensionMessage.ts`, `state-keys.ts` 등 상태 관리 파일들이 Caret의 고유 기능을 지원하기 위해 확장되어 충돌합니다.
  - **UI 컴포넌트**: `SettingsView.tsx`, `ApiOptions.tsx` 등 주요 UI 컴포넌트가 Caret의 i18n 시스템과 기능 통합으로 인해 크게 변경되었습니다.
  - **삭제/수정 충돌**: Cline에서 삭제된 `generic-system-prompt.ts` 파일을 Caret이 수정하여 사용 중입니다.
