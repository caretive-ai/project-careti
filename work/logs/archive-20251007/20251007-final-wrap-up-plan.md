# 작업 계획: 최종 정리, 원칙 보강 및 새 세션 준비

## 1. 목표
이전 커밋을 롤백하고, 마스터의 추가 지시사항(핵심 개발 원칙)을 작업 계획에 명시적으로 추가한 뒤, 모든 변경사항을 다시 커밋한다. 마지막으로, 보강된 원칙을 포함한 최종 컨텍스트를 생성하여 다음 세션을 준비한다.

## 2. 작업 단계

### **Phase 1: 커밋 되돌리기 및 문서 보강**

- **Step 1.1: 이전 커밋 롤백**
  - **명령어**: `git reset --soft HEAD~1`
  - **설명**: 가장 최근의 커밋(`docs(merging): ...`)을 취소하고, 변경된 파일들을 스테이징 상태로 되돌린다.

- **Step 1.2: 작업 계획 문서에 핵심 원칙 추가**
  - **대상 파일**: `work/plan-recovery-and-migration-v2.md`
  - **추가할 내용**:
    ```markdown
    ## 2. 핵심 작업 원칙 (Master's Directives)

    - **머징 영향 중심 사고**: 단순 디버깅에 매몰되지 않고, 항상 Cline 변경이 Caret에 미치는 구조적 영향을 중심으로 문제를 분석하고 해결한다.
    - **Caret 주석 원칙 준수**: Cline의 `src/` 디렉토리 내 파일을 수정할 때는, 반드시 `// CARET MODIFICATION:` 주석과 함께 명확한 변경 사유를 기재한다.
    - **최소 침습 및 `caret-src` 우선**: 신규 기능 구현이나 대규모 수정이 필요할 경우, Cline 코드 직접 수정을 최소화하고 `caret-src/` 내에 독립적인 모듈로 구현하는 것을 최우선으로 한다.
    ```
  - **실행**: `read_file` 후 `replace_in_file`을 사용하여 문서 상단에 위 내용을 추가한다.

### **Phase 2: 재커밋 및 새 세션 준비**

- **Step 2.1: 변경사항 재커밋**
  - **명령어**: `git add . && git commit --amend --no-edit`
  - **설명**: 롤백된 변경사항과 원칙이 보강된 작업 계획을 합쳐, 이전과 동일한 커밋 메시지로 다시 커밋한다.

- **Step 2.2: 최종 컨텍스트 생성 및 새 세션 시작**
  - **작업**: `new_task` 도구를 사용하여, 보강된 핵심 원칙을 포함한 최종 요약 컨텍스트를 생성하고 다음 세션으로 작업을 넘긴다.
