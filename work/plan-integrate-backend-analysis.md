# 백엔드 분석 결과 병합 및 정리 계획

이 계획은 `work/analysis-of-102-modifications.md` 문서에 `work/backend-analysis-results.md`의 내용을 통합하고, 분석 필요 목록을 정리하는 작업을 체계적으로 수행하기 위해 작성되었습니다.

## 1. 목표

- 두 분석 문서를 하나의 일관된 보고서로 병합합니다.
- 새로 분석된 파일들을 '분석 완료' 섹션으로 이동시킵니다.
- 중복된 '분석 필요' 섹션을 통합하고, 이미 분석된 항목을 제거하여 최종적으로 분석이 필요한 파일 목록만 남깁니다.

## 2. 작업 단계

### 1단계: 파일 읽기
- 원본 문서 `work/analysis-of-102-modifications.md`를 읽습니다.
- 추가 분석 내용이 담긴 `work/backend-analysis-results.md`를 읽습니다.

### 2단계: 내용 병합
- `backend-analysis-results.md`의 분석 결과 테이블을 `analysis-of-102-modifications.md`의 `## 📋 분석 완료된 백엔드 파일` 섹션에 추가합니다.
- 가독성을 위해 `### 📋 백엔드 파일 재분석 (컨플릭트 원인 중심)`이라는 새로운 소제목 아래에 추가 분석 내용을 배치합니다.

### 3단계: 분석 필요 목록 정리
1.  **분석 완료 파일 목록 추출**: `backend-analysis-results.md`의 테이블에서 분석이 완료된 파일 경로 목록을 추출합니다.
2.  **기존 분석 필요 목록 추출**: `analysis-of-102-modifications.md`에서 아래 두 섹션의 파일 목록을 모두 추출합니다.
    - `## 🤖 수동 분석 필요 파일` > `### 백엔드`
    - `## 🤖 추가 분석 필요 파일 (백엔드 - 24개)`
3.  **최종 분석 필요 목록 생성**:
    - 두 목록을 합치고 중복을 제거합니다.
    - 위에서 추출한 '분석 완료 파일 목록'에 포함된 파일들을 제거합니다.
4.  **문서 구조 재구성**:
    - 기존의 `## 🤖 추가 분석 필요 파일 (백엔드 - 24개)` 섹션을 완전히 삭제합니다.
    - `## 🤖 수동 분석 필요 파일` 섹션을 `## 🤖 추가 분석 필요 파일 (백엔드)`로 제목을 변경하고, 위에서 생성한 최종 목록으로 내용을 교체합니다. 프론트엔드 목록은 그대로 유지합니다.

### 4단계: 최종 파일 작성
- 위의 변경 사항을 모두 적용하여 `work/analysis-of-102-modifications.md` 파일을 덮어씁니다.

## 3. 예상 결과
- `work/analysis-of-102-modifications.md` 파일이 추가 분석 내용을 포함하여 업데이트됩니다.
- 문서 하단에는 중복 없이, 실제로 분석이 필요한 백엔드 파일 목록만 명확하게 정리되어 남게 됩니다.
